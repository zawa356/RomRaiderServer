## 1. 判断の扱い

**合意:** ユーザーとBD-001〜008の会話で確定した方針。
**委任判断:** 「細かな判断・文書改訂はChatGPT判断でよい」との指定により、設計文書で確定した詳細方式。
**条件付:** 実ECU／クライアント互換性／ライセンス確認が条件であり、技術判断を保留した部分。条件付のものは勝手に「実証済み」にならない。

| ADR | 区分 | 決定 | 理由・棄却した代替 |
| --- | --- | --- | --- |
| ADR-001 | 合意 | Serverが製品正本、Agentが車載正本の2リポジトリ | 二重サーバー／第三の共通repoを避ける |
| ADR-002 | 合意 | 既存PoCの継承義務なし。RRBridge Java Agentの再利用を第一候補 | 既に成立した介入手段を捨てる開発コストを避ける |
| ADR-003 | 合意 | データは常にspool永続化後に送信 | ネットワーク不達・Server停止から計測を独立 |
| ADR-004 | 合意 | 保存確定ACK＋at-least-once＋冪等なServer保存 | TCP受信とDB commitを混同しない |
| ADR-005 | 合意 | 最新データと過去滞留の両立、未ACKの自動破棄禁止 | リアルタイム性と原本保全 |
| ADR-006 | 合意 | PostgreSQLにサンプル原本を無期限保持 | 単純なセルフホスト構成。DBバックアップはインフラ側 |
| ADR-007 | 合意 | 走行・計測実行・セグメント・タスクを分離 | 再起動・項目切替・複数走行タスクを表現 |
| ADR-008 | 合意 | 取得イベントが原本、行・列指定生データ検索をMCPに公開 | 集計のみに閉じず解析可能。任意SQLは公開しない |
| ADR-009 | 合意 | AIは宣言的計画、Serverは版・承認範囲、車載が最終安全判断 | AI指示の直接ECU適用を避ける |
| ADR-010 | 合意 | 複数タスクを保管し、車両ごとの実行は原則1件 | K-Line帯域と競合防止 |
| ADR-011 | 合意 | 走行中のプロファイル切替は目標だが未検証時は無効 | ECU通信と安全入力が未実証 |
| ADR-012 | 合意 | 定義・ECU対応項目はAgentが発見しServerに同期 | 未定義／未取得パラメーターの強制適用を避ける |
| ADR-013 | 合意 | Agent通常／AI起動モード、手動操作優先、局所復旧 | Server／AI依存の無い基本計測 |
| ADR-014 | 合意 | サーバー数値監視・解析履歴はLLM非依存・追記型 | プッシュされないAIやチャット切替に対応 |
| ADR-015 | 合意 | MCPとAgent APIの独立認証・権限分離 | 車載認証がAI管理権限に昇格しない |
| ADR-016 | 合意 | Server受信基盤→RRBridge→実ECU→MCP→Supervisor→高度解析 | 主要基盤の成立を早期に試し、実機を初手のブロッカーにしない |
| ADR-017 | 委任判断 | HTTPS/JSONの製品Agent API v1 | 実装／デバッグ容易。性能問題があれば実測で圧縮検討 |
| ADR-018 | 委任判断 | 全件コミットまたは全件拒否の原子的バッチACK | 誤ACKと部分成功の複雑な処理を避ける |
| ADR-019 | 委任判断 | UUIDの不変record ID、同runのseq重複拒否 | 再送／遅延順序／端末再起動で衝突を回避 |
| ADR-020 | 委任判断 | profile revisionを不変定義として先行登録 | 後着の原本を正しい単位・項目で解釈 |
| ADR-021 | 委任判断 | 初版Device認証は端末固有ランダムBearer＋TLS | 個人運用に過度な認証基盤を導入しない |
| ADR-022 | 委任判断 | 本番MCPは標準OAuth/OIDCを第一候補。既製IdPを使う | 匿名アクセスや自作簡易認証を避ける。Live互換は要検証 |
| ADR-023 | 委任判断 | 原本JSONB＋同一transactionの項目別検索射影 | 保存再現性と条件検索の両立 |
| ADR-024 | 委任判断 | 車両単位のDB取り込み直列化とcommit済みwatermark cursor | 後着データと並列commitでもページ結果を安定化 |
| ADR-025 | 委任判断 | ローカルSQLite WALをspool第一候補とする | record ID別ACK、隔離、再起動復元が単純 |
| ADR-026 | 委任判断 | 新旧送信バッチを交互に処理 | 最新の鮮度と過去分の回収の両方を前進させる |
| ADR-027 | 委任判断 | MCP Queryは制限付きAST＋keyset cursor、SQL非公開 | 柔軟な解析と権限／資源制限を両立 |
| ADR-028 | 委任判断 | PostgreSQL／FastAPI系でServerを構成（候補） | PoC知見と保守性。SDK／依存版は実装時固定 |
| ADR-029 | 委任判断 | シンプルなServer Worker、初版Redis／Kafka無し | 常時LLM不要、個人運用の複雑性を抑制 |
| ADR-030 | 委任判断 | 管理CLIで端末登録・承認・認証情報更新 | MCU/MCPからの無制限な管理操作を避ける |\n| ADR-031 | 委任判断 | MCPのquery_telemetryで任意record_idを起点に同一runの次／前N観測を一括検索（is_present条件、cursor継続） | 1値1コールを防ぎ、Aの次の値を直接参照できるようにする |

## 2. 技術検証結果を必要とする項目

| 課題 | 未確認点 | 設計の暫定対処 | 試験 |
| --- | --- | --- | --- |
| TV-01 | Java Agentが実ECUデータを安定取得できるか | RRBridge再利用第一候補、実ECU確認までは合成と区別 | VAL-001 |
| TV-02 | 走行中安全判定が実車・K-Line負荷で成立するか | 走行中切替を初期無効化、独立入力がないなら拒否 | VAL-005 |
| TV-03 | プロファイル生成とLogger定義・ECU適合 | 定義と実取得確認の区別、未確認を拒否 | ECU-T05 |
| TV-04 | 独立取得の安全入力とフォールバック競合 | Supervisor統括、RRBridge保護、競合時に停止 | ECU-T07〜09 |
| TV-05 | ChatGPT通常／LiveのOAuth／書込みツール互換 | 既製認可基盤、読取りMCPから検証、無認証本番不可 | MCP-T01/MCP-T11 |
| TV-06 | SQLite spoolのWindows電源断耐性・ドライバ配布条件 | WAL・FULL候補、強制終了／実負荷で検証 | AG-T02/AG-T06 |
| TV-07 | PostgreSQLのロックと巨大検索の実測性能 | 車両単位直列化、各種索引、低負荷なら簡素構成 | DB-06/DB-11 |
| TV-08 | RomRaider・依存物のGPL等、製品配布 | 第三者バイナリ再配布せず公開前に調査 | OPS公開ゲート |
| TV-09 | エンジンON/OFF識別の自動化 | 信頼可能な観測がない場合unconfirmed、ロガー停止では確定しない | FR-SESSION |
| TV-10 | JSON正規化・Decimal／float・比較ハッシュの境界 | 原本と派生検索値の一致を契約試験 | CT-003／CT-012 |

この表は設計未完ではなく、**外部に依存する受入条件**を管理する。実装前の安全拒否を削除してはいけない。

## 3. 設計改訂時の規則

- 上位の要件を変更しない範囲では、委任された技術判断を実測結果により変更できる。
- APIのフィールド意味／必須属性を変える場合は、Wire契約・OpenAPI・Agent実装・契約テストを同時改訂し、非互換なら新プロトコル版へ。
- 実車安全条件の拡張は、**検証記録が先**。設計書変更だけでは車載実装の制限を解除しない。
- DB原本の自動削除、未保存ACK、匿名本番MCP、任意ECUコマンドの公開は、現行要件に抵触するため単なる技術判断では追加不可。
- PoCから製品への移行時、既存のPoC文書やコードの状態表示を「製品実装済み」と書き換えない。
